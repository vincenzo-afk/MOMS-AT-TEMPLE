# Decisions and Known Issues

## Decisions (session 1)

| # | Decision | Why | Reversible? |
|---|---|---|---|
| D1 | TypeScript + Vite 8 + Three.js 0.186 + React 19, versions pinned exactly in package.json | README default stack; current maintained releases | yes |
| D2 | All 3D assets generated by **Blender Python scripts run headless** (`blender -b`), not hand-modelled in the live session | reproducible, diffable, one command rebuilds everything; the live Blender MCP connection is used for inspection | yes; any asset can later be replaced by a hand-made .blend exported with the same names |
| D3 | **Vertex-colour art direction** (no texture maps yet) with a shared palette and roughness/metal library materials | coherent look across 37 assets, tiny files, no UV work for the first pass | yes; UVs and textures can be added per asset |
| D4 | Collision from **Blender box proxies** (`COL_`/`WALK_`) plus a custom kinematic controller, no physics engine | the game needs walking, steps and camera collision, not rigid-body physics; zero dependencies | yes |
| D5 | Characters are **procedural** on one shared skeleton; **in-place** animation with engine-driven movement (no root motion), and stride-synchronised playback | consistent rig for all NPCs; speed always matches the feet | partly; clips are keyed procedurally, and hand-keyed or mocap clips can replace them with the same names |
| D6 | Each character GLB carries its own copy of the clips | NPCs of different heights need their own hip offsets | yes |
| D7 | Single authoritative `GameSession` state; WorldView derives visuals; consequence restorations via `triggeredByFlags` | README §5.8 and the save/visual consistency requirement | — |
| D8 | Deterministic Living Record IDs (`<type>:<subject>`) and reward claim IDs | idempotency prevents duplicate rewards and records | — |
| D9 | Save: one main slot + rolling backup + quarantine of corrupt data, in IndexedDB | README §5.10 recovery requirement | yes; more slots can be added |
| D10 | 1 real second = 1 world minute (24-minute day) | visible day cycle and regrowth in a short session | yes (`MINUTES_PER_SECOND`) |
| D11 | Default movement: walk 2.2 m/s, Shift run 5.0 m/s (bindings as in the README) | 1.65 m/s felt slow for a 90 m map; the walk clip plays ×1.33 so the stride still matches | yes |
| D12 | Opening sequence is **skippable from the first viewing** (README says "after it has been experienced once") | player-friendly; it is short (11 s) and can be disabled in Settings | yes, by hiding the button on first run |
| D13 | The browser cannot quit: the title screen says "close the tab" instead of showing a Quit button | README §13.2 allows a browser-appropriate equivalent | — |
| D14 | Pending audio entries are never fetched; UI and interaction cues use synthesized blips | avoids 404 noise; no fabricated audio files | yes |
| D15 | Browser tests run on installed **Microsoft Edge** | the Playwright Chromium download stalled at 0 bytes here | yes (`PW_CHANNEL`) |
| D16 | Religious personnel are not depicted; NPC roles are secular (resident, gardener, artisan, trader, elder). Temple doors stay closed | README §4.1: the tradition must be researched before depicting religious roles; "Monks" kept only as the project title | — |
| D17 | The temple placement is scaled ×1.25 in the level (asset authored at 11 × 15 m) | landmark read too small in the courtyard; collision scales with it | yes |
| D18 | npm cache: this machine's global npm cache points at an unavailable `E:\.npm-cache`, so installs were run with `--cache <temp dir>` | the global config was not modified | — |

## Conflicts between README and reality

- **README §14 file structure** lists `src/tests/` and per-system data folders; data lives in single files under `src/data/` (small enough), and unit tests sit beside the code they test. Browser tests are in `tests/e2e/`.
- **README §8.7** asks to validate texture references; there are no textures yet (D3).
- **Milestone D** asks for a "properly designed body mesh": what exists is a rigged, weighted, animated **first-pass procedural** character. It is deliberately labelled as such in the CHARACTER_BIBLE and is not a final character.
